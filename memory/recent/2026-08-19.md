## Cascade production UI redesign and deployment (archive of August 18 work)

- Finished the Cascade-branded design pass on the long-lived `cascade-main` branch and pushed commit `4dae801` (`feat(ui): finish the Cascade design pass across every surface`). The final eight legacy surfaces converted were `admin.html`, `settings.html`, `team_settings.html`, `invite_form.html`, `overrides.html`, `source_write_setup.html`, `confirmed.html`, and the embed generator.
- The pass reorganized admin into four labelled groups, split profile/team settings into focused cards, composed the guest confirmation as a single card, and gave the embed generator a full-width live preview. It also corrected several cross-page defects found during visual review: clipped slot-list overflow, mobile theme-toggle/card collisions, poor vertical centering on tall screens, over-wide booking inputs, light-painted native controls under forced dark mode, and stacked admin team checkboxes.
- Verification at completion reported 812 passing tests plus light/dark, desktop, and phone-width visual checks. The deployed source and verified UI commit were clean at handoff.
- Deployed the branded build to `https://calendar.cascade.tax` through the private `~/Dev/cascade-calendar` operations repository. Cloud Build produced image `1.15.1-cascade.5`; the ops configuration pinned its digest, staged it to the VM over IAP, and restarted the service. The container was healthy, and live sign-in plus Arthur's real booking page were checked in both themes.
- Production's stored custom theme exactly matches the Cascade palette. The branded code deliberately emits no custom override for that exact palette, allowing the built-in Cascade design system to render without a competing database theme; the deployment did not modify production data.
